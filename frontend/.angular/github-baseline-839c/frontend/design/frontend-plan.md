# Минимальный план фронтенда

Цель: законченный небольшой продукт по [целевому макету](target-ui.md). Делаем только действия, которые уже поддерживает бэкенд. После каждого этапа проверяем результат в браузере на реальных данных.

## 0. Что уже есть

- Загрузка и раскрытие досок, показ колонок и карточек.
- Подборка важных задач по кнопке.
- Создание карточки и перенос в другую колонку с повторной загрузкой досок.
- Нужно вручную подтвердить создание карточки без обновления страницы; перенос уже проверен пользователем.

## 1. Закончить структуру доски

- Создать доску из интерфейса.
- Выбирать одну открытую доску и создавать в ней колонку.
- Показать понятные пустые состояния для доски и колонки.

**Готово, когда:** с пустой базы можно создать доску, колонку и карточку без Swagger и ручной перезагрузки.

## 2. Закончить действия с карточкой

- В подробностях карточки менять название, описание, срок и приоритет.
- Перенос и создание карточки сохраняются после перезагрузки страницы.
- Удалять карточку; удалять доску через её меню с подтверждением.
- Не отправлять пустое название; показывать ошибку, если запрос не удался.

**Готово, когда:** пользователь может исправить или удалить ошибочно созданную карточку и видит результат каждого действия сразу.

## 3. Оформить экран по макету

- Простая боковая панель досок, верхний блок важных задач, горизонтально прокручиваемые колонки.
- Читаемые карточки с приоритетом и сроком; подробности и перенос открываются по нажатию.
- Удобный вид на узком экране, понятные подписи полей и заметный фокус клавиатуры.

**Готово, когда:** основные действия понятны без подсказок и экран выглядит аккуратно на компьютере и телефоне.

## 4. Проверить и показать продукт

- Заменить устаревший шаблонный тест Angular. Проверить поведение: загрузка досок и ошибка загрузки; создание доски, колонки и карточки с правильным телом запроса; перенос с правильным ID; обновление экрана только после успешного ответа; отказ от пустого названия. HTTP подменять тестовым контроллером Angular.
- На бэкенде проверить правила: перенос внутри доски проходит, перенос в колонку другой доски отклоняется; подборка важных задач исключает готовые колонки и выдаёт нужный порядок; пустое название отклоняется. Тесты должны проверять результат и ошибки, а не повторять строки реализации.
- Один раз пройти основной сценарий вручную с настоящими Spring Boot и PostgreSQL: создать доску → колонку → карточку → изменить → перенести → удалить. Проверить сохранение после перезагрузки страницы.
- Обновить README: запуск фронта и бэкенда, скриншоты, краткий сценарий демонстрации и честное описание подбора важных задач.

**Готово, когда:** проект запускается по инструкции, перечисленные тесты проходят, основной сценарий проверен целиком, а демонстрацию можно провести за несколько минут. Процент покрытия строк сам по себе не является критерием.

## Не включаем в этот план

Новый ИИ-сервис, авторизацию, drag and drop, обновление/удаление колонок, сложные анимации и отдельную архитектурную переработку. Эти задачи не нужны, чтобы текущий проект стал хорошим учебным продуктом. Добавлять их можно только после готового основного сценария и при отдельной причине.
